# 开发交接约定

这是内容约定，不要求拆成七个文件。小组件可以用一份交接说明完成。

| 项目 | 需要的依据 | 常见问题 |
|---|---|---|
| 参考观察 | 来源标识、画面区域或时间点 | 猜测原作者使用的工具或代码 |
| 适配决策 | 改了什么，为什么适合当前产品 | 内容不兼容却照搬截图 |
| 设计参数 | 实现中实际使用的具名参数 | JSON 参数与 CSS 不一致 |
| 交互状态 | 触发、反馈、数据变化和恢复 | 按钮好看却无法操作 |
| 素材清单 | 相对路径、来源、能否再分发 | 交接包依赖他人电脑的绝对路径 |
| 接入边界 | 模拟、本地、远程状态，以及输入和事件 | 没有持久化却显示“已保存” |
| 验证记录 | 视口、操作、观察结果和缺口 | 只写“已测试”，没有范围 |

## 状态表示例

| 状态 | 触发 | 可见结果 | 数据变化 |
|---|---|---|---|
| 未选择 | 初次加载或取消 | 显示预览，可以选择 | 没有选中项 |
| 已选择 | 点击选择 | 按钮和状态文字明确选中 | 仅本地内存状态 |
| 切换外观 | 选择另一种外观 | 预览和已选说明同步更新 | 不向服务器写入 |
| 减少动态效果 | 系统或浏览器设置 | 禁用倾斜和过渡 | 选择行为不变 |

没有网络请求的 Demo 不必模拟网络故障。之后需要接入真实服务时，再按实际失败路径扩展约定。

## 最小交接内容

1. 启动方式和最先尝试的操作。
2. 哪些特点是观察、推测或主动适配。
3. 设计参数与素材位置。
4. 状态表和接入位置。
5. 已验证内容与尚未验证的部分。

声称离线可用前，要阻断网络运行。键盘与对比度检查不等于完整无障碍审计。
