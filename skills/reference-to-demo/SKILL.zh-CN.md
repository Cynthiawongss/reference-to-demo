# 参考设计转可交接 Demo

把参考中有价值的特点落实到用户的产品。保留任务范围、产品用词、业务规则，以及用户已选定的实现。交付物使用用户指定的语言。

## 1. 确认要转移什么

查看参考和目标产品。无法访问图片、视频、网址或项目时，指出缺口，不描述没看过的内容。只有缺失信息妨碍有效推进时才提问；否则说明假设，完成用户要求的最小范围。

| 依据类型 | 记录什么 | 示例 |
|---|---|---|
| 观察到的 | 来源及图片区域或时间点 | 大标题后有斜向光带 |
| 推测的 | 可能的实现方法，标明是推测 | 可以用 CSS 渐变模拟表面效果 |
| 主动适配的 | 改动及其产品原因 | 将图片里的文字改成 HTML 文本 |

截图能证明外观，不能证明隐藏状态或原始代码。先提取层级、对比、材质和节奏，再考虑颜色。复用目标产品的设计参数与组件；没有现成体系时，只定义 Demo 用得上的参数。

## 2. 先定义交互，再处理视觉

对相关动作说明：**触发方式 → 可见反馈 → 数据变化 → 恢复方式**。根据实际行为补状态，不为填模板而增加流程。

| 行为 | 必须区分的含义 |
|---|---|
| 预览或选择 | 本地选中不代表已保存或已购买 |
| 远程提交 | 等待、成功、失败和重试对应真实请求 |
| 禁用操作 | 说明业务限制的原因 |
| 装饰性动效 | 键盘和触屏也能完成同样的操作 |

用户只要分析或线框图时，到相应交付物为止。需要实现时优先沿用已有技术栈；独立 HTML 适合小型便携 Demo，但不是硬性要求。使用可用且允许使用的本地素材，或说明原创替代方案。演示本地选择不需要额外建设后端。

## 3. 实现一套一致的版本

保持设计参数、展示内容和交互状态一致。标明模拟数据和模拟响应。控件应改变对应状态并给出反馈，不能只看起来可以操作。

动效不能妨碍文字阅读、键盘焦点、触屏操作和减少动态效果设置。关键动作不能依赖悬停、精确指针位置或动画播放完毕。修改时保留用户认可的方向，只调整指定维度及必要关联部分。

## 4. 分别检查操作过程和渲染结果

运行核心动作、撤销或修正路径、键盘操作，以及相关宽屏和窄屏布局。已接入真实请求的部分再核对请求路径。选择类 Demo 要检查选择、切换选项、清除选择和刷新，避免误报持久化能力。

代码检查、行为检查和渲染检查分别记录。按信息层级、轮廓、表面效果和操作反馈对照参考，解释有意适配。记录视口、操作、实际结果和缺口。不要编造还原度分数，未打开渲染页面就不能声称完成视觉检查。声称离线可用之前，要在阻断网络的环境中运行。

## 5. 按任务规模交接

完整交接时阅读[交接约定](references/handoff-contract.zh-CN.md)，提供可运行源码、必要素材、启动说明、设计参数、交互状态、接入边界和验证记录。局部修改可以只交付修改文件与简短说明。

说明哪些是可编辑源文件、哪些是生成文件，以及本地、模拟、远程行为分别在哪里，下一步要接入什么。接手者应能复现核心动作并知道哪些已经检查。制作 Demo 本身不等于授权发布或修改线上后端。

具体案例见 [Prism Pass](examples/prism-pass/brief.zh-CN.md)：原创活动通行证参考，包含两种外观、本地选择和明确的接入事件。
